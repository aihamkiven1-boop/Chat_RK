# Telegram Events Bot

بوت Telegram لإدارة الفعاليات والمسابقات داخل مجموعات Telegram: إنشاء فعالية أسئلة سريعة (SpeedQuiz)، مشاركة الأعضاء، احتساب النقاط مع مكافأة سرعة، ترتيب المتصدرين، وإعلان النتائج النهائية.

## ملخص المنتج

- المشرف ينشئ فعالية ويضيف أسئلة ويبدأها.
- الأسئلة تُعرض بمؤقت زمني، ويُقبل من كل عضو إجابة واحدة لكل سؤال فقط.
- الإجابة الصحيحة السريعة تمنح نقاطًا أكثر (من 100 إلى 150).
- لا تُقبل الإجابات بعد انتهاء وقت السؤال.
- ترتيب للمتصدرين لكل فعالية ولكل مجموعة.
- فعاليات مستقلة تمامًا لكل مجموعة، وحدث نشط واحد فقط لكل مجموعة.
- استعادة آمنة بعد إعادة تشغيل التطبيق دون فقدان الفعاليات أو تكرار النقاط.
- قاعدة بيانات SQLite محلية.

> ملاحظة: لم يتم اختبار هذا البوت على Telegram الحقيقي؛ الاختبارات مغطاة بوحدة اختبارات محلية تعمل بقاعدة بيانات مؤقتة.

## المتطلبات

- Python 3.11 أو أحدث.
- مكتبات حسب `requirements.txt`.

## التثبيت والتشغيل

```bash
python -m venv .venv
source .venv/bin/activate          # على Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # ثم ضع BOT_TOKEN داخل .env
python -m app                      # تشغيل Long Polling
```

انظر `OPERATIONS.md` للتفاصيل، و`SECURITY.md` للممارسات الأمنية.

## Telegram و Privacy Mode

- البوت يحتاج أن يرى **الإجابات النصية** داخل المجموعة ليعالجها كإجابات.
- **Privacy Mode** مفعّل افتراضيًا للبوتات في المجموعات، وقد يمنع البوت من رؤية الرسائل العادية.
- لإتاحة ذلك: عطّل Group Privacy في **BotFather**، أو أضِف البوت مشرفًا في المجموعة بحسب احتياج البوت، ثم أعد إضافته للمجموعة إذا لزم.
- لا يمكن تغيير هذا برمجيًا من داخل البوت.

## هيكل المشروع

```
telegram-events-bot/
├── app/
│   ├── main.py            # نقطة الدخول والتوصيل (Long Polling)
│   ├── config.py          # الإعدادات من البيئة
│   ├── constants.py       # الحالات والثوابت
│   ├── database.py        # اتصال SQLite والـ migrations
│   ├── models.py          # dataclasses للكيانات
│   ├── container.py       # Composition root للخدمات
│   ├── migrations/        # ملفات SQL للـ schema
│   ├── repositories/      # طبقة SQL فقط
│   ├── services/          # قواعد العمل والحالات
│   ├── games/             # استراتيجيات الألعاب
│   ├── handlers/          # معالجات Telegram
│   └── utils/             # أدوات مساعدة
├── tests/                 # اختبارات pytest
├── scripts/               # نسخ احتياطي وبذر بيانات تجريبية
├── data/                  # قاعدة البيانات (data/event_bot.sqlite3)
├── backups/               # نسخ احتياطية
└── logs/                  # سجلات
```

## حدود الإصدار الأول

- لعبة واحدة مفعلة: **SpeedQuiz** (سؤال نصي وإجابة نصية). ألعاب صحيح/خطأ والاختيار من متعدد موجودة كواجهات غير مفعلة.
- `ConversationHandler` غير مستخدم؛ الفعالية تعتمد على الأوامر فقط.
- لا توجد خصومات نقاط.
- SQLite مناسب لنسخة واحدة/عملية واحدة.
- الإلغاء متاح من حالة التسجيل فقط وفق آلة الحالات المحددة.
